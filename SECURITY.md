# Security

Keep the owner application private and store service credentials only in runtime secrets. Never publish an unprotected owner Worker or trust user-supplied identity headers as authentication.

Do not put vulnerability details containing credentials, client links or personal data in public issues. Use GitHub private vulnerability reporting if it is enabled. Otherwise open a minimal issue asking for a private contact route, without exploit details or sensitive data. There is no guaranteed response time. Restrict an affected installation while arranging a report.

Before client use, complete docs/VALIDATION.md, including anonymous owner denial, cross-gallery denial, private-note isolation and revoked-link checks.
